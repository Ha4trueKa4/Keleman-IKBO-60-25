# Практическая работа 2 — Визуализатор графа зависимостей

**Дисциплина:** Конфигурационное управление · **Вариант 15**

Инструмент визуализации графа зависимостей для менеджера пакетов
**apt (Ubuntu)**. Готовые менеджеры пакетов и сторонние библиотеки для
получения зависимостей не используются — индекс репозитория скачивается
и разбирается самостоятельно. Граф обходится алгоритмом **BFS с
рекурсией**, а текстовая визуализация строится на языке диаграмм
**PlantUML**.

Работа выполняется в пять этапов; каждый этап завершается стандартно
оформленным коммитом (Conventional Commits).

## Требования

Python 3.11+. Используется только стандартная библиотека
(`configparser`, `argparse`, `urllib`, `gzip`, `lzma`, `re`);
сторонние зависимости отсутствуют. Для работы с реальным репозиторием
нужен доступ в интернет.

## Этап 1. Минимальный прототип с конфигурацией

Единственный источник настраиваемых параметров — конфигурационный файл
формата **INI** (секция `[analyzer]`).

| Параметр | Назначение | Обязательный |
|----------|------------|:---:|
| `package` | имя анализируемого пакета | да |
| `repo_url` | URL индекса apt или путь к файлу репозитория | да |
| `test_mode` | режим работы с тестовым репозиторием (`true`/`false`) | нет |
| `version` | версия пакета (пусто — последняя в индексе) | нет |
| `ascii_tree` | выводить зависимости в виде ASCII-дерева | нет |
| `max_depth` | максимальная глубина анализа (целое ≥ 0) | да |
| `filter` | подстрока для исключения пакетов (пусто — без фильтра) | нет |

| # | Требование | Где реализовано |
|---|------------|-----------------|
| 1 | Параметры из INI-файла | `config.load_config` |
| 2 | Все семь настраиваемых параметров | `config.Config` |
| 3 | Вывод параметров «ключ = значение» | `main.format_params`, флаг `--show-config` |
| 4 | Обработка ошибок всех параметров | `config.py`, `examples/err_*.ini` |

```
$ ./run.sh --show-config
Параметры анализа (из config.example.ini):
  package    = bash
  repo_url   = http://archive.ubuntu.com/ubuntu/dists/noble/main/binary-amd64/Packages.gz
  test_mode  = false
  version    = (любая)
  ascii_tree = true
  max_depth  = 3
  filter     = (нет)
```

| Пример конфига | Ошибка |
|----------------|--------|
| `examples/err_no_section.ini` | отсутствует секция `[analyzer]` |
| `examples/err_no_package.ini` | не задан `package` |
| `examples/err_no_repo.ini` | не задан `repo_url` |
| `examples/err_bad_bool.ini` | `test_mode` не `true`/`false` |
| `examples/err_bad_depth.ini` | `max_depth` не целое число |
| `examples/err_negative_depth.ini` | `max_depth` отрицательный |

Каждая ошибка выводится в `stderr`, код возврата — `1`.

## Этап 2. Сбор данных

Информация о зависимостях берётся напрямую из индекса репозитория apt —
файла `Packages` (поддерживаются `Packages`, `Packages.gz`,
`Packages.xz`). `repo_url` может быть URL или путём к локальной копии
индекса. Сам `apt` и сторонние библиотеки не используются.

Как это работает (`src/apt_repo.py`):

1. `load_index` скачивает индекс (`urllib`) и распаковывает его
   (`gzip`/`lzma`).
2. `parse_index` делит текст на записи по пустой строке и разбирает
   поля `Ключ: значение` (строки-продолжения склеиваются).
3. `find_package` выбирает запись пакета нужной версии `version`; если
   версия не задана — последнюю в индексе.
4. `direct_dependencies` собирает прямые зависимости из полей
   `Pre-Depends` и `Depends`:
   - ограничения версий отбрасываются: `libc6 (>= 2.38)` → `libc6`;
   - квалификатор архитектуры отбрасывается: `python3:any` → `python3`;
   - из альтернатив `a | b` берётся первая (как делает apt по умолчанию);
   - повторы удаляются.

```
$ ./run.sh --config examples/apt_git.ini
Прямые зависимости git 1:2.43.0-1ubuntu7:
  libc6
  libcurl3t64-gnutls
  libexpat1
  libpcre2-8-0
  zlib1g
  perl
  liberror-perl
  git-man
```

| Пример конфига | Что показывает |
|----------------|----------------|
| `examples/apt_curl.ini`, `apt_git.ini` | прямые зависимости реальных пакетов |
| `examples/apt_version.ini` | выбор заданной версии |
| `examples/apt_bad_version.ini` | версия не найдена (выводятся доступные) |
| `examples/apt_unknown.ini` | пакет не найден |
| `examples/apt_bad_url.ini` | индекс недоступен (HTTP 404) |
